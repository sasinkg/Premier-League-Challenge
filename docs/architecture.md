# Architecture — Premier League Challenge

## Overview

Premier League Challenge is a fully client-side React app with no custom backend server. All data persistence goes through Firebase, and standings data is delivered as a static JSON file bundled at deploy time.

---

## Data Sources

### Live Standings

Standings are fetched from the [football-data.org](https://www.football-data.org) API **at deploy time** by a GitHub Actions workflow, not at runtime by the browser.

```
GitHub Actions (nightly + every push to main)
  → curl football-data.org/v4/competitions/PL/standings
  → writes public/standings.json
  → Vite bundles it into dist/
  → Firebase Hosting serves it as a static file
```

The frontend fetches `/standings.json` on load:

```ts
// src/api/premierLeague.ts
const res = await fetch("/standings.json");
const data = await res.json();
```

No API key is ever exposed to the browser.

### User Data (Firebase)

Firebase handles authentication and all user-generated data:

- **Firebase Auth** — Google sign-in
- **Firestore** — groups, members, and weekly predictions

---

## Firestore Schema

```
groups/{groupId}
  name: string
  code: string          — 6-character join code
  createdAt: Timestamp
  ownerId: string

  members/{userId}
    role: "owner" | "member"
    displayName: string
    email: string
    joinedAt: Timestamp

  predictions/{weekKey}   — weekKey = Monday date (YYYY-MM-DD)
    users/{userId}
      uid: string
      displayName: string
      email: string
      teams: TeamInfo[]   — ordered predicted table
      submittedAt: Timestamp
```

## Scoring

For each team in a prediction:

```
error = |predicted_position − actual_position|
```

Total score = sum of all errors across 20 teams. Lower is better.

The diff view shows per-team deltas:
- `✓` — exact match
- `▲N` — team is N places higher in real table than predicted
- `▼N` — team is N places lower in real table than predicted

Position badges are colour-coded by error magnitude:

| Error | Colour |
|---|---|
| 0 | Neutral |
| 1–2 | Amber |
| 3–5 | Orange |
| 6+ | Red |

## Game Rules

- Season starts **15 August 2025**
- Before the season: unlimited drag changes (for setup)
- During the season: **one drag per week**, resets every Monday
- Users may revert their drag before submitting
- Predictions are scoped per group per week

## CI/CD

| Workflow | Trigger | Purpose |
|---|---|---|
| `ci-checks.yml` | PR → main | Lint + audit + build + CodeQL |
| `firebase-hosting-pull-request.yml` | PR opened/updated | Preview deploy to Firebase |
| `deploy.yml` | Push to main / nightly schedule | Fetch standings + build + deploy live |
| `screenshot.yml` | After deploy succeeds | Screenshot live site → commit to docs/ |

## Environment Variables

All secrets are stored in GitHub repository secrets/variables and injected at build time via Vite's `import.meta.env`.

| Variable | Type | Purpose |
|---|---|---|
| `VITE_FOOTBALL_API_KEY` | Secret | football-data.org API key |
| `VITE_API_BASE_URL` | Var | football-data.org base URL |
| `VITE_FIREBASE_API_KEY` | Secret | Firebase project API key |
| `VITE_FIREBASE_AUTH_DOMAIN` | Var | Firebase auth domain |
| `VITE_FIREBASE_PROJECT_ID` | Var | Firebase project ID |
| `VITE_FIREBASE_STORAGE_BUCKET` | Var | Firebase storage bucket |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | Var | Firebase messaging sender |
| `VITE_FIREBASE_APP_ID` | Var | Firebase app ID |
